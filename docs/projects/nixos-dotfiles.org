* Current System
:PROPERTIES:
:CUSTOM_ID: current-system
:END:
The MSI laptop is the primary live host and uses the =#nixos= flake output.
The =#desktop-amd= output is a guarded bootstrap target whose machine-specific
hardware acceptance is still future work.

For current branch, generation, output, build, activation, and promotion state,
start with [[../README.org][the documentation dashboard]] and its latest handoff.

Durable ownership:

- Hyprland behavior lives in =config/hypr/hyprland.lua=.
- Quickshell owns the desktop shell surfaces under =config/quickshell/=.
- =scripts/theme-select= and =theme/styles.json= own global theme state.
- Clean Emacs is the active Emacs configuration; Doom is retired.
- NVF and its Sky configuration live in the standalone =neovim-nvf=
  repository; they are not part of the MSI system closure.
- Ollama is retired from the intended system configuration.
- QMK udev support remains MSI-wide, while the Vial and QMK applications are
  absent.  VS Code is configured through Home Manager for Linux.
- MSI disk, filesystem, initrd, platform, and microcode facts are tracked in
  =hosts/msi/hardware-configuration.nix=.  The MSI target evaluates and builds
  purely; =nrs= and =nrb= no longer request impure evaluation.

* Entry Points
:PROPERTIES:
:CUSTOM_ID: entry-points
:END:
- =flake.nix=: host outputs and shared special arguments.
- =hosts/msi/=: current MSI host entrypoint.
- =hosts/desktop-amd/=: AMD bootstrap entrypoint.
- =system/modules/=: reusable NixOS modules.
- =home/modules/=: Home Manager modules and live-link ownership.
- =config/=: application-native configuration.

* Normal Commands
:PROPERTIES:
:CUSTOM_ID: normal-commands
:END:
#+begin_src sh
git status --short --branch

nix --extra-experimental-features 'nix-command flakes' \
  build --print-out-paths \
  '.#nixosConfigurations."nixos".config.system.build.toplevel' \
  --no-link --no-write-lock-file --show-trace

nrs
hyr reload
systemctl --user restart quickshell
#+end_src

The standalone build does not activate the machine.  =nrs= is the separate
interactive activation command.

* Direction
:PROPERTIES:
:CUSTOM_ID: direction
:END:
- Keep =main= as the checkpoint lane.
- Work in small, measurable slices with rollback.
- Preserve the intentional live-link workflow and validate resolved live bytes.
- Move machine facts into =hosts/<host>/= without hiding reusable mechanisms.
- Fix confirmed defects before performance experiments.
- Treat QMK udev access as an accepted system capability; install Vial or QMK
  tooling only for an explicit firmware task, separate from editor,
  Quickshell, and GC work.

Current post-checkpoint lanes:

- =work/nixos-maintenance=: permanent system-maintenance integration lane.
  Keep build verification separate from live activation, promote accepted work
  to =main= only by strict fast-forward, then realign the lane with the new
  checkpoint.  The next maintenance decision remains the deferred read-only
  store measurement no earlier than =2026-08-18=.
- Quickshell: no later slice is selected; take fresh action-labelled
  measurements before performance work, and keep dual-output validation
  separate.
- Emacs: finish the active language acceptance decision, then optimize only
  observed daily-use friction.
- VS Code: refine the current Linux Home Manager profile from measured use;
  adapt remaining macOS choices without importing Darwin-specific pins.
